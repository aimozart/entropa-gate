# Unfreeze 2 (slice 5): what is reopened and why
Reason: the second sealed round (frozen binary 95bf7f51..., commit 1fde821) found two real differences (reviewer's report, 2026-11-18): (1) a DUPLICATED KEY in a checkpoint line was accepted (last one wins); (2) an UNKNOWN EXTRA KEY in a checkpoint line was accepted silently, so unsigned data could ride in a checkpoint line with no alarm. The anchor decoder refuses both.
Files reopened (only these): crates/ledger/src/raw.rs, crates/ledger/src/store.rs. New tests anywhere. After the slice: a new freeze commit, hash list, and a binary from the same container build; the round-1 and round-2 binaries stay on disk.
Rule implemented: checkpoint lines go through the strict JSON reader (duplicate keys refused) with a CLOSED key set per version (v1: root, size, timestamp, proposer_pubkey, signature; v2 adds counter and prev); a duplicate, unknown or missing key is a format error; numbers must be whole and not above 2^53 - 1 (the bound the anchor decoder uses).
