## 1. What already exists (so this design adds only what is missing)
`entropa-council` (stage S12c, accepted) already provides, tested and mutation-checked: `admit()` (only a **signed, human-accepted** `decision.recorded` becomes a precedent; its text is the deterministic closed-code rendering, never vault text), `Index` (a pinned, exact, dense index: model descriptor, sorted entries, `index_hash`, exact cosine search with an id tie-break, k from 1 to 5), `precedent_reference()` (the unsigned `precedent.referenced` event for a retrieval), the `precedent.referenced` event schema (ids, `index_hash`, `k`, `followed`), the replay harness and the planted-fault harness. S12d-b/c would add the lexical index of section 4 and the retrieval evaluation of section 7. Nothing in this document requires a cloud service to be correct; the cloud options of section 6 are storage and (optionally) embedding choices behind the same trait.

## 2. The corpus
**A precedent** = one admitted decision: the finding class, severity, the decision, its closed reason code, the change kind, and the references (never text). Rendered as one short line, for example `decision f-12 decision=accept reason=evidence_sufficient change=test attested=false` plus the finding's class and severity codes (the renderer is `render::line`, tested for a closed character set and for refusing any canary).
**Size (assumed):** about 5,000 precedents of about 150 tokens and 600 bytes (750,000 tokens, 3 MB raw); growth about 100 precedents a week (the council decides at most 12 items a session, plus the per-decision automatic records; 100 is a generous allowance).
**Never in the corpus:** vault text, anything a model wrote, PHI-equivalent values, canary tokens, unsigned or unaccepted entries, entries of another tenant (section 8).
**Revocation:** an entry is never edited. A precedent found wrong is removed from the next index build by a signed `precedent.revoked` event (new, `human-principal`, closed code for the reason), listed in the index manifest; old index hashes stay verifiable.

## 3. Retrieval is two stages, and the first needs no model
1. **Structured filter (exact):** tenant, action class, finding class, severity. These are closed codes, so this stage is a plain comparison: deterministic, free, reproducible on any machine.
2. **Ranking inside the filtered set:** either (L) a **lexical** score over the rendered closed-code terms, or (V) a **dense** vector score from an embedding model. Section 4 defines L, section 5 pins V.
**Recommendation (decision D1): L is the source of truth; V is an optional second index that exists to show the AWS RAG pattern.** Reasons: the vocabulary is a few hundred closed codes, so embeddings add little over exact term overlap; L has no model call on the retrieval path (so no PHI-equivalent text can reach a model, no per-query cost, nothing to pin or to drift, and it still works when the clouds lapse); and the reviewer's service-eligibility rule says Titan embeddings were **not found** on AWS's HIPAA-eligible list, so a model call with PHI-equivalent text is not allowed until confirmed. The dense index only ever embeds the closed-code rendering, the same text as L.

## 4. The lexical index and its hash (deterministic, integer arithmetic only)
**Terms:** split the rendering on space, `=`, `:` and `,`; keep tokens of `A-Za-z0-9._-`; lower-case. A precedent's term set is the sorted, deduplicated list of `field=value` pairs (for example `decision=accept`, `class=missing_approval`, `severity=high`, `change=test`), so a term is a closed code, never a word.
**Score (no floats, so identical on every machine):** with integer weights per field (default: class 4, decision 3, severity 2, change 2, reason 1), `score(q, d) = 1000 x W(q ∩ d) / W(q ∪ d)` using integer division, where `W` sums the weights of the terms in the set. Results are ordered by score descending, then by precedent id ascending; `k` is 1 to 5; **a precedent scoring below the abstention threshold (default 400) is not returned**, so "no relevant precedent" is a possible, recorded answer.
**Index hash:** `BLAKE3("entropa-council-index-l-v1" 0x00 || u32be(len) scorer descriptor || u32be(n) || for each precedent in sorted id order: u32be(len(id)) id || u32be(len(tenant)) tenant || u32be(term count) || for each term in sorted order: u32be(len) term)` (**the tenant is part of the hash**, added in S12d-b: two indexes that differ only in who may retrieve a precedent must not share a hash; revoked precedents are not part of it, they are part of the **manifest hash**: `BLAKE3("entropa-council-manifest-v1" 0x00 || u32be(n) || sorted admitted ids || u32be(n) || sorted revoked ids)`; the **memory hash** is `BLAKE3("entropa-council-memory-v1" 0x00 || index_hash as 64 ASCII hex bytes || sorted ids)`, at most 5 ids). The scorer descriptor is the canonical JSON of the field weights and the threshold, so a weight change changes the hash. The dense index keeps the hash already implemented (`Index::index_hash`: model id, dimension, normalisation, sorted ids and the little-endian float bytes).
**Index versions are ledger facts:** the scheduler signs `index.built` (new): `index_hash`, `kind` (lexical or dense), `n_entries`, `previous_index_hash`, `manifest_hash` (the sorted list of admitted precedent ids and revocations). A decision's `index_hash` can therefore always be resolved to a build and its contents.

## 5. The pinned embedding model (for the optional dense index V)
**Pinned choice (decision D2): Amazon Titan Text Embeddings V2, model id `amazon.titan-embed-text-v2:0`, 1,024 dimensions.** Facts read from AWS's documentation on 2026-10-21 [AWS docs: docs.aws.amazon.com/bedrock/latest/userguide/titan-embedding-models.html]: up to 8,192 input tokens or 50,000 characters; output size 1,024 (default), 512 or 256; English optimised (100+ languages in preview); on-demand and provisioned inference; throttled by requests per minute. **Price: $0.00002 per 1,000 input tokens (batch $0.00001) [AWS price file]**. The page I read does not say whether the model normalises its output, so the design **normalises to unit length itself** and pins the descriptor `{id: amazon.titan-embed-text-v2:0, dim: 1024, normalization: "unit-l2-client"}`; the descriptor is part of the index hash, so a different model, dimension or normalisation is a different index by construction.
| Alternative | Why not the default |
|---|---|
| Titan V2 at 512 or 256 dimensions | halves or quarters the index; worth a planted-case comparison (section 7) before choosing, because the corpus is tiny and size does not matter |
| Cohere Embed v4 on Bedrock | listed at $0.12 per 1M input tokens as an AWS Marketplace software line in the price file: a second vendor and a different billing path, against the "one provider per cloud" rule |
| a Google embedding model on Vertex AI (`gemini-embedding-001`) | the pricing page lists a Gemini Embedding input price of $0.00015 per 1,000 "count" online and $0.00012 batch **[snippet; the unit is "count", not tokens: if it is tokens this is about $0.15 per 1M, eight times Titan]**; `text-embedding-005` $0.00002 per 1,000 characters **[snippet of an old blog post]**; would put the dense index on the GCP side, and keeps the static rule "GCP = Gemini" only if the owner counts embeddings as Gemini-family: his call |
| no embedding model (L only) | the recommendation for the source of truth |
Reproducibility caveat: a managed embedding model can change behind the same id; the index therefore stores the vectors it was built with, retrieval never re-embeds the corpus, and only the **query** is embedded at search time, so two retrievals over the same index hash differ only if the query embedding differs (a model update); the planted-case suite (section 7) is re-run on any change and a failing model is not adopted.

## 7. Planted-case evaluation of retrieval (the quality gate)
A **suite generated with the real crates** (so the precedents are real protocol outcomes): for each of the finding classes, N admitted precedents plus planted cases with a known right precedent. Measured for each index (L, and V if built), at k = 1, 3 and 5:
| Measure | Definition | Proposed acceptance |
|---|---|---|
| **recall@3** | the planted right precedent is among the first three | at least 90% for exact-match cases, 70% for near-match cases |
| **MRR** | mean reciprocal rank of the right precedent | reported, no gate (compared between L and V) |
| **abstention** | cases with **no** relevant precedent return nothing (score below the threshold) | at least 95% |
| **poisoning** | an unsigned, an unaccepted, a rejected and a revoked entry **never** appear | 100% (a hard zero) |
| **injection** | a precedent whose rendering contains planted instruction-like text or a canary-shaped string is never admitted or never takes effect | 100%; the renderer's closed alphabet and the canary refusal make this a decoder-level guarantee |
| **cross-tenant** | a query for tenant A never returns tenant B's entries (row-level security, G1 item 12) | 100% |
| **followed rate** | how often the deciding agent's decision matches the top precedent when the precedent is right, measured later from `precedent.referenced` (`followed`) | reported; it informs promotion (section 8), not a gate |
| **reproducibility** | the same index hash and query give byte-identical results in two containers; for the dense index the query embedding is compared with a tolerance and the ranking exactly | 100% for L; for V the ranking must be equal |
| **drift** | rebuilding the index from the same manifest gives the same hash | 100% |
Cost of the whole suite: embedding 200 cases x 150 tokens = 30,000 tokens = **$0.0006** (Titan); the lexical suite costs nothing. The suite is re-run on every change of the scorer weights, the threshold, the embedding model or dimension; a failure blocks adoption (the same rule as for reviewer models in the council design).

## 8. How a retrieved precedent enters the decision event
1. **Before deciding**, the agent's harness retrieves (k at most 5, the abstention threshold applied) and writes a signed `precedent.referenced` event: `decision_ref`, `index_hash`, the ids, `k`, `followed = not_judged` (the event and `precedent_reference()` already exist).
2. **The decision event itself carries `memory_hash`** (new optional field on `agent.invocation`, `policy.decision` and `tx.screened` records): `BLAKE3("entropa-council-memory-v1" 0x00 || index_hash || sorted ids)`, 64 hex, so the decision is bound to exactly the precedents it saw, without repeating the ids. A verifier recomputes it from the referenced event; a mismatch is a finding.
3. **After the outcome**, the council's evaluator appends a `precedent.referenced` event for the same `decision_ref` with `followed` yes, no or partly (the latest wins); `followed` and the outcome feed section 7's followed rate and the promotion rule.
4. **The context packer (S13) records the precedent ids inside the context hash** it already writes into every decision event, so the harness proves what the model was shown.
5. **Retrieval is evidence, never authority:** the Cedar gate and the human gate decide; a precedent can inform, never allow (council rule 1). Precedents of other tenants are not retrieved unless explicitly marked shareable (decision D5).
**Promotion** (council D8): a precedent that recurs three times with the same outcome across at least two sessions becomes a `promote_precedent` finding, to be turned into a Cedar policy or a test, after which the decision no longer needs retrieval.

## 9. Threats
| Threat | Mitigation |
|---|---|
| **Poisoning of the corpus** | `admit()` takes only signed, human-accepted decisions; revocation by signed event; the manifest is hashed and recorded in `index.built`; tested (sections 1, 7) |
| **Prompt injection through a precedent** | the rendering is a fixed template of closed codes with a closed alphabet (tested); the retrieved text is delimited as data by the packer; models have no tools |
| **Index tampering or silent replacement** | the index hash is in every decision (`memory_hash`) and every build is a signed event; a file that does not hash to the recorded value is refused on load |
| **Stale or drifted index** | the age of the build is shown with the decision; weekly rebuild after the council session closes; model/dimension/weight changes need the evaluation to pass |
| **Retrieval treated as authority** | council rule 1, enforced by the gates; the packet and the page label precedents as evidence |
| **Cross-tenant leakage** | the structured filter is tenant-first; row-level security (G1 item 12) applies to the read layer; a test per section 7 |
| **PHI-equivalent data reaching an embedding model** | not possible by construction: only the closed-code rendering is embedded, a canary in it is refused, and L needs no model |
| **Flooding the corpus** | at most the admitted accepted decisions of a session enter; a per-week cap on additions (default 200) with the surplus carried over |
| **Cost surprise** | the dense variant's query cost is 1.08M tokens a month ($0.02); a request budget in the harness and the AWS cost levels (docs/ARCHITECTURE-AWS-SHOWCASE.md section 8.2) apply |

- Lexical overlap of closed codes finds similar decisions, not wise ones; precedents encode past choices, including past mistakes the council has not yet caught.
- All Google prices here are search-result summaries of pages that do not render as text (read 2026-10-21; a direct read failed), plus the owner's paste: **UNVERIFIED** until read from the Cloud Billing catalog.
