# Threat model (STRIDE per component). Written 2026-10-20 in S0b; living document.
Scope: the re-rust audit log. Components marked *planned* do not exist yet; their rows are the design requirements for the stage that builds them.
Assets: log integrity (no silent rewrite or reorder), record authenticity (who recorded what), signing key, availability of checkpoints. Out of scope: correctness of the AI decisions recorded (a signature proves who recorded what, not that the decision was right).

| Component | S Spoofing | T Tampering | R Repudiation | I Info disclosure | D Denial of service | E Elevation |
|---|---|---|---|---|---|---|
| **Log** (crates/core: Merkle tree, checkpoints, receipts) | Receipt verified against an attacker-chosen pubkey: verifiers must obtain the pubkey out of band; `verify_receipt` takes it as an argument. | Rewrite or reorder history: inclusion and consistency proofs plus signed checkpoints detect it (property tests in crates/core/tests/properties.rs). **Gap F4:** record encoding is ambiguous when a payload contains NUL. | Operator denies a checkpoint: signed checkpoints are non-repudiable by the key holder. | Records are stored verbatim: callers must hash or minimise before appending; synthetic data only in this repo. | Unbounded record size or count: limits belong to the ingest tier (not enforced in core). | None: no privileged operations in core. |
| **Sequencer / ingest** (crates/api) | Partner identity by API key or JWT: legacy code, reviewed in a later stage. | Reordering before append: single writer, order fixed at append. | Submitter denies a submission: receipts bind record to checkpoint. | Logs must never contain secrets. | Flooding: rate limits exist in legacy code; unverified here. | Legacy admin and billing surface is a prune candidate (docs/PRUNE-PLAN.md). |
| **Signer** (CheckpointSigner: Probe in process; KmsSigner for AWS KMS) | A backend returns another key's signature: `checkpoint_with` now verifies before returning (audit S0). | Wrong-length key or signature from a client: rejected (audit S0). | Key use is attributable through KMS CloudTrail (production). | In-process Probe keys live in memory: tests only; production signs in KMS, the key never leaves it. | KMS throttling or outage: signing returns `SignError`, the log is left unchanged, caller retries. | KMS key policy and IAM least privilege (S1, S6); nobody but the signer role may call Sign. |
| **MCP server** (*planned*, S2) | Only a local stdio client; no network listener. | Read-only tools: no write path to the log. | Every call logged with arguments minus secrets. | Never return keys, raw secrets or unbounded record dumps; size limits per tool. | Rate limiter and input size limits (S2d). | No shell, filesystem or network tools; denied by hook (S2g). |
| **Approval gate** (*planned*, S3/S4) | Approver identity bound to a signing key in the approval record. | Approval records are appended to the log, so they cannot be edited later. | Approve and deny are signed and logged. | Approval text may contain sensitive context: minimise. | A stuck approval blocks the action (fail closed by design). | Cedar default-deny policy (S4); no action runs without a matching approval. |
| **Witness** (*planned*, S5) | Witness key distribution out of band. | Witness checks consistency between checkpoints, so a split-view log is detected. | Witness statements are signed. | Witness sees only checkpoints, never records. | Witness outage must not block appends. | Witness has no write access to the log. |

## Build and supply chain
- Dependencies checked by cargo-deny and cargo-audit (ADR 0003); lockfile committed and builds use --locked.
- CI actions pinned by commit SHA; no long-lived cloud keys in CI (OIDC later, S6).
- Secrets: never in the repo; gitleaks gate is scheduled for S0c (Paxel readiness).
