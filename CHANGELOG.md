- Two closed-vocabulary labels added at the end of `LabelCode` for the standards-retrieval stage (R1): `corpus_version` (evidence.change; a corpus version was sealed, or refused because a source changed under the same version name) and `retrieval_record` (evidence.access; a retrieval was answered or abstained). No new control code (the E1 codes are reused). Additive; existing labels, controls, kinds and signatures unchanged. Plain-English sentences included. Two older pinned tests were updated for the appended labels (events.rs e3 list; controls_labels.rs c1 now a contiguous run).
- Two closed-vocabulary labels added at the end of `LabelCode` for the E1 self-assessment, both `evidence.control_check` labels: `crypto_inventory` (a listing of the TLS settings of our own hosts) and `log_integrity_check` (a ledger verified from start to end, or the failure). Eight control codes added at the end of `ControlCode` (names only, no framework text): `pci_dss_10_3_4`, `pci_dss_12_3_3`, `dora_rts_art_6`, `dora_rts_art_12`, `nist_800_53_au_9`, `nist_800_53_au_10`, `eu_ai_act_art_12`, `eu_ai_act_art_19`. One older test (`t1` in `triage_labels.rs`) now checks the five triage labels as a contiguous run after `council_decision` instead of as the very tail.
- Five closed-vocabulary labels added at the end of `LabelCode` for claims triage: `claims_triage` (platinum.decision), `policy_verdict`, `approval_requested`, `approval_denied` (evidence.policy), `case_outcome` (evidence.control_check). Additive; existing labels, kinds and signatures unchanged.
## 0.2.0 (2026-10-20), entropa-core breaking change
- **Record encoding v2** (ADR 0011): versioned, length-prefixed, canonical. Fixes F4: different `(payload, label)` records can no longer share bytes or leaf hashes. `Some("")` and `None` labels are now different records.
- `encode_record` and `decode_record` return `Result<_, RecordError>`; `decode_record_or_marker` is a display-only helper; new `MAX_FIELD_BYTES` (1 MiB per field) and `RECORD_FORMAT_VERSION`.
- v1 (NUL-separated) bytes are rejected; nothing live depended on them.
- **Removed (breaking, found by cargo-semver-checks against 0.1.3):** the retired blockchain-era API: modules `chain`, `block`, `beacon` and their items (`Chain`, `ChainError`, `Block`, `Transaction`, `BIG_BANG`, `block_digest`, `rollback_detected`, `beacon::sample`, `beacon::sample_live`). entropa-core is now the transparency-log library only. See docs/evidence/s0e-semver-checks-forced.txt.
- `verify_receipt` now binds `receipt.index` and `checkpoint.size` to the inclusion proof (RFC 6962/9162 rules) via the new `merkle::verify_inclusion_at`; a receipt claiming a position its proof was not built for no longer verifies (ADR 0016). `verify_inclusion` is unchanged and does not bind position.
- Dependencies: removed unused `reqwest` and `sha3`; `serde_json` is dev-only. entropa-kms is publishable (`aws` feature optional).
- Checkpoint digest uses a fixed-width u64 size (identical bytes on 64-bit).
- `CheckpointSigner`/`checkpoint_with`, `entropa-kms`, lints and tooling: see docs/AUDIT-S0.md and docs/AUDIT-STANDARDS.md.
